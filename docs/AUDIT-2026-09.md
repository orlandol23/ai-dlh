# Security and architecture audit, September 2026

Audited state: `e7398b5` on `main`, 2026-09-05. Statuses are current as of
2026-09-07 and name the pull request that closed each item, so this file can be
read against `git log` rather than trusted.

One of six repositories audited in the same pass. This one had the most
findings, which is proportional to it having the most surface: a public API
with paid AI calls behind it, a custodial wallet that spends gas, and a queue
that writes to an append-only contract.

## Method

One read-only reviewer per repository, in parallel, no paid or external calls.
This repository's reviewer reproduced the logger failure with the repository's
own winston and axios versions rather than reasoning about it. On top of that,
one deterministic check across all six: no `.env` tracked at any point in
history, `.gitignore` covering it, zero secret patterns, zero
`pull_request_target`.

Every HIGH finding was verified in the code before it was written down. One of
them (H4, the missing fence) did not come from the reviewer: it was found by
applying the pattern from the Java pipeline's audit to this queue.

## Patterns shared with the other five repositories

1. **"Exactly-once" was at-least-once in both queue repositories** (this one
   and `event-driven-payout-pipeline`), through the same gaps: post-claim
   transitions did not check the lock's identity, and nothing was recorded
   between the external effect and the journal. Fixed the same way in both.
2. **The Slither gate was decorative**, for the same reason it had been in
   `swiss-defi-optimizer`: `crytic/slither-action@v0.4.1` installs
   `slither-analyzer 0.11.4` on Python 3.9, which ignores the `fail-on`
   threshold. Confirmed in the CI log. Fixed in PR #37.
3. **CI hygiene.** `permissions: contents: read` landed in PR #37. This
   repository uses only first-party `actions/*`, so nothing to SHA-pin.
4. **Documentation asserting what the code did not do.** Here,
   `MASTER_PLAN.md` said "wallet spoofing is not a hole today"; it was, through
   signature replay (see the decision on `auth.getNonce`). Corrected in the
   same PR as this file.

## High

| # | Finding | Where | Fix | Status |
|---|---|---|---|---|
| H1 | The logger's `printf` called `JSON.stringify(meta)` and threw `TypeError` on a circular object (an `AxiosError`). The exception escaped the router's `catch`, so the cross-provider fallback never ran: a provider outage became a request failure. | `server/utils/logger.ts`, `providers/router.ts` | `safeStringify` with a `WeakSet` of visited objects; `try/catch` inside `printf`. 8 tests, 6 of them red against the old logger. | **Fixed**, PR #37 (merged `da6637f`). |
| H2 | `logger.warn(msg, err)` with a raw `AxiosError`: winston spreads an `Error` into its enumerable properties, so `config.headers.Authorization: Bearer <DASHSCOPE_API_KEY>` became an ordinary nested field. It did not reach disk only because H1 threw first. | `providers/router.ts` | Never pass the raw error; redact keys matching `SENSITIVE_KEY` in the logger as a second line of defence. | **Fixed**, PR #37. |
| H3 | Post-claim transitions used `.where(eq(id))`: no status, no lock, no nonce. A worker whose stale lock had been reclaimed wrote over the current holder, and could rewrite the journal under it, pointing the holder's recovery at the wrong nonce. | `blockchain-queue.service.ts` | `blockchain_lock_token` minted by every claim; every later write fenced by `heldBy` (id + processing + token); the journal throws `LockLostError` on zero rows and the failure handler treats it as "not mine", never as a retry. A `CHECK` constraint makes the lock a pair (token and timestamp together or neither). Proven against a real PostgreSQL 16. | **Fixed**, PR #38 (open at time of writing). |
| H4 | A broadcast whose acknowledgement was lost (socket reset, RPC timeout, gateway 502) left a row with no nonce, so the retry took the fresh-send path and the append-only contract recorded the completion twice. No crash required; a bad network moment was enough. The PR that introduced the journal had documented this window as "crash between broadcast and UPDATE", which understated it. | `blockchain-queue.service.ts`, `web3.service.ts` | Sign locally, journal the signed hash, then broadcast. A signed transaction carries its final hash before any node sees it, so there is no longer a moment where a transaction exists and the row cannot name it. A signing test against a real `ethers.Wallet` and a fake JSON-RPC node proves the ordering against the real library. | **Fixed**, PR #38. |
| H5 | AI quota and gas are drainable: the rate limiter keys on `user.id`, and a `user.id` is created by any wallet signature (free, offline). No daily or global ceiling. A comment in `ai.router.ts` claimed there was one. | `ai.router.ts`, `trpc.ts` | A global daily counter checked before any provider call; a dedicated limiter on `auth.login`. | **Open.** Planned as Phase 0b in `MASTER_PLAN.md`. |

## Decisions taken by the owner, 2026-09-06

Each is a plan item until the PR that implements it links back to this row.

| Topic | Decision | Reasoning |
|---|---|---|
| `moduleTopic` on-chain, free text, permanent | Record the decision now; hash the topic (`bytes32`, per ADR-0004) on the next redeploy. Until then: a README section stating the topic is public and immutable, and a warning in the UI before generation. | The deployed contract is frozen by its Etherscan verification, so hashing requires a redeploy that is not otherwise happening. |
| `cert.getByHash` undoes pseudonymisation | Replace the transaction hash in the certificate URL with an opaque token. | The endpoint links a transaction hash to the learner's real `walletAddress`. Because `msg.sender` on-chain is the custodial wallet, this endpoint is the only source of that link, and scanning the contract's transactions on Etherscan is enough to enumerate it. Truncating the address does not help: the truncated form still matches Etherscan. A secret-link certificate is the correct shape. |
| Premium tier self-assignable | Premium **is** a paid subscription for access to more expensive models: that is Phase 1 of the master plan. Until Phase 1 ships: remove the option from the UI and keep the field server-side, so no logged-in user can route to the paid model for free. | `updatePreferences` accepted `preferredTier: 'premium'` unchecked, and that routes to the paid model. The interim step costs nothing and stops the leak; the real gate is the billing work already planned. |
| Signature login without a server challenge | `auth.getNonce` server-side now; EIP-4361 (SIWE) later, as already planned in C3. | The nonce was minted on the client. A malicious site could build the message with the right domain, ask the victim to `personal_sign`, and replay it within the five-minute window. Server-issued, single-use nonces close the vector in ~30 lines. |
| Seven-day JWT in `localStorage`, `logout` is a no-op | `token_version` column on the user, checked in `verifyToken`, incremented on logout. | Makes logout real and provides a panic button. Short TTL with refresh is the better design but touches the whole client; the column is an afternoon. |

## Medium and low, apply-only

- [x] Slither: `setup-python@v5` 3.11 + `pip install slither-analyzer==0.11.6` + explicit `--fail-medium`; the always-failing, always-swallowed `size-contracts` step removed. PR #37.
- [ ] `npm audit fix` without `--force`: closes `qs` / `body-parser` (server runtime, moderate). The critical is `vitest` (dev only).
- [ ] `helmet`, `app.disable('x-powered-by')`, an explicit `express.json({ limit })`.
- [ ] Winston file transports on Railway's ephemeral disk, without rotation: console only in production.
- [ ] `NODE_ENV` defaults to `'development'`, which silently disables the placeholder-`JWT_SECRET` guard: make it required.
- [ ] `jwt.verify` without `{ algorithms: ['HS256'] }`.
- [ ] `.env.example` says `/health` is exempt from the rate limit; the code exempts only `/healthz`.
- [ ] `x-region` is not in the CORS `allowedHeaders`, so routing to Qwen is unreachable from a browser.
- [ ] A `failed_permanent` record whose nonce is still pending never returns to the worker; `cert.getByHash` then denies a certificate that exists on-chain. Consult receipts one last time before parking.
- [ ] README: one line stating that `recordCompletion` is permissionless and `totalCompletions` can be inflated by third parties; the proof is "the custodial wallet attested", not "it is on the chain".
- [ ] Prompt injection through `topic` in `prompt-builder.ts`: an explicit delimiter around user text.

## What holds up

- Secret hygiene is clean in the tree and the history.
- The atomic claim was correct all along; the problem was what came after it.
- Errors are closed to the client as a discipline.
- The documentation is honest as a rule ("built vs designed"), which is what
  made every divergence above visible and fixable.
